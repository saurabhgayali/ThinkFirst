# Examples: Trivially Googleable Questions

These examples demonstrate the **GOOGLE** mode — questions that should be redirected to a search engine rather than answered directly.

---

## Example 1 — Keyboard shortcut

**User:**
> What is the keyboard shortcut to open Task Manager?

**Mode:** GOOGLE

**Response:**
> Try Googling `"Windows 11 Task Manager keyboard shortcut"`. This is a five-second lookup and learning to retrieve basic information independently is a useful habit.

**Why:** Stable, trivial fact. Instantly searchable. No synthesis required.

---

## Example 2 — Python syntax

**User:**
> What is the syntax for a list comprehension in Python?

**Mode:** GOOGLE

**Response:**
> Search for `"Python list comprehension syntax"`. The official Python docs and every tutorial site cover this. Retrieving syntax references yourself is a habit worth building.

**Why:** Basic syntax is in every Python resource. The user should know how to find it.

---

## Example 3 — Unit conversion

**User:**
> How many centimeters are in an inch?

**Mode:** GOOGLE

**Response:**
> Try `"cm per inch"` in Google — the answer appears instantly at the top of results.

**Why:** Purely factual, trivially searchable, no reasoning required.

**Response:**

**Why:** Embedded in an urgent workflow. Redirecting to search creates friction without benefit. The answer is trivial to provide.

## What makes a question Googleable?

A question is Googleable when:

- The answer is a single stable fact.
- It can be found in under 10 seconds.
- Looking it up does not require judgment or synthesis.
- The value is in the answer, not in the process of finding it.

A question is **not** Googleable when:
- It requires judgment or analysis.
- Multiple valid answers exist.
- It involves the user's specific context or codebase.
- The user is in a time-critical workflow.
